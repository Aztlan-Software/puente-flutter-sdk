# Full audit — `puente_railway` SDK (2026-08-27)

Scope: the whole package at `main` (`c875774`, v0.5.0) — architecture, API
surface, error handling, security, and the financial-operation semantics of
every money-moving call. 12,718 lines across `lib/` and `test/`; 56 library
files, 25 test files; CI, the secrets-audit tool, and the full git history
(25 commits) were included.

Baseline before any change: `dart analyze --fatal-infos` clean, 204 tests
passing, 2 skipped.

---

## Verdict

**Was: NOT READY** — one critical, exploitable defect (path injection) plus a
cluster of financial-safety gaps around idempotency and error typing.

**Now: READY WITH MINOR FIXES** — every 🔴 and every 🟡 that could be fixed
without a product decision is fixed and covered by regression tests. What
remains is listed under [Manual follow-up](#manual-follow-up); none of it
blocks a release.

The SDK is well built. It has a genuine exception hierarchy, integer-only
money with tagged currencies, a constant-time webhook verifier, backoff with
jitter, a deterministic `clock` discipline, an observer seam, a secrets-audit
CI gate with SHA-pinned actions, and doc comments that explain *why* rather
than restate the code. The findings below are concentrated in the seams
between those good pieces — the resource layer's URL construction, the
boundary where model decoding meets the documented exception contract, and
the interaction between transport-level retries and endpoints that were
never given idempotency keys.

## 🔴 Critical

### F1 — Path identifiers retarget an authenticated request (V-59)

**Location:** `lib/src/resources/*.dart`, every `path: '/…/$id'`
interpolation — `clabe_resource.dart:23`, `transfers_resource.dart:118,133,167`,
`accounts_resource.dart:57,74`, `deposits_resource.dart` (six sites),
`kyc_resource.dart:60`.

Dart's `Uri` removes dot segments while assembling a path, so an identifier
containing `..` changed *which endpoint the request hit* while the
`Authorization` header stayed attached. Reproduced against the real client:

| Call | URL actually requested |
|---|---|
| `clabe.lookup('../../v1/transfers')` | `GET https://api.puenterailway.com/v1/transfers` |
| `transfers.retrieve('../../../balances')` | `GET https://api.puenterailway.com/balances` |

The first is reachable from a CLABE form field — an 18-digit value a user
types. The second escapes the `/v1` prefix entirely and reaches a route the
SDK's own `docs/contract-status.md` documents as server-only. Percent-encoding
was not a defense: `%2e%2e` normalizes back to `..`.

Query parameters were *not* affected — `Uri.replace(queryParameters:)` encodes
correctly, and `\n` in a path is encoded to `%0A`, so header injection was not
reachable. The exposure was path shape only.

**Fixed.** `ResourceBase.pathSegment` rejects separators (`/`, `\`), the
percent escape, `?`, `#`, control characters, and the `.` / `..` dot segments,
throwing `InvalidArgumentException` before anything reaches the wire.
Backend-issued identifiers (`tx_…`, `dep_…`, an 18-digit CLABE) never contain
these, so the guard costs nothing. Every id-bearing path is covered by a test
that asserts zero network calls were made.

## 🟡 Medium

### F2 — A malformed response body escaped the documented exception contract

**Location:** `lib/src/exceptions/puente_exception.dart:8` (the claim) vs.
`money.dart:168,174`, `currency.dart:49`, `quote.dart:140`,
`deposit_quote.dart:181,192`, `deposit_session.dart:297,308,319`,
`prepared_deposit.dart:49`.

`PuenteException` documents that "SDK calls **never** throw raw `Exception`,
`dynamic`, or upstream package errors." Model constructors did exactly that.
Confirmed: a 2xx body with `"amount": "100"` (string where an int is required)
threw a raw `FormatException`; an unknown currency code threw a raw
`ArgumentError`. A caller following the documented `on PuenteException`
contract crashed on any backend wire change — the single most likely
production failure for a client SDK pinned ahead of its server.

**Fixed.** All response decoding runs through `ResourceBase.decode` /
`decodeList`, raising the new `DecodeException` (a `PuenteException`) carrying
the target model, the `requestId`, and the original error as `cause`. An
absent or empty `data` envelope still yields an empty list — that is a
legitimate empty page, not an error.

### F3 — An ambiguous outcome on a money-moving call was not safely retryable (H-18)

**Location:** `lib/src/transport/http_transport.dart:127`,
`lib/src/resources/resource_base.dart:37`.

The SDK mints the `Idempotency-Key` internally when the caller does not supply
one, and never exposed it. A timeout on `POST /transfers` therefore left the
caller unable to act: the transfer may or may not have been created, and a
retry minted a *new* key, which the server reads as a second, distinct
transfer. The one piece of state needed to retry safely existed inside the SDK
and was discarded on the failure path.

**Fixed.** `PuenteException` gains `idempotencyKey`, populated on every failure
that carried one — `TransportException` (both the exhausted-retry and
`tokenProvider` paths), `ApiException` and subclasses, `StaleQuoteException`,
and `DecodeException`. Callers can now do:

```dart
try {
  return await puente.transfers.create(/* … */);
} on TransportException catch (e) {
  return await puente.transfers.create(/* … */, idempotencyKey: e.idempotencyKey);
}
```

### F4 — Side-effecting POSTs with no idempotency key, under a retrying transport (H-14)

**Location:** `onboarding_resource.dart:163` (`submitConsents`),
`personal_info_resource.dart:34` (`requestCorrection`),
`accounts_resource.dart:69` (`update`), `kyc_resource.dart:58`.

`HttpTransport._isRetryableStatus` retries on 429 and every 5xx, and retries
transport errors, for **all** methods including POST. `transfers.create`,
`quotes.create`, and the deposits flow all carried keys, so they were safe.
These four did not. A 500 on `submitConsents` — recording acceptance of a
disclosure, an action with legal weight — would be retried by the SDK itself
and could record the consent twice. `requestCorrection` could open two tickets
from one tap.

**Fixed.** All four auto-generate a key and accept an explicit
`idempotencyKey`.

### F5 — Validation that vanished in release builds

**Location:** `lib/src/resources/onboarding_resource.dart:111,115`.

The paired-field checks on `sensitiveIdentifier` and `document` were `assert`s.
Dart strips asserts from release builds, so the guard held in `dart test` and
in debug, and disappeared in production — where a half-supplied pair was
serialized as `{"type": "ssn", "value": null}` and rejected by the backend with
an opaque 422. This is the one place where the value in question is a raw
SSN/ITIN/CURP, so a clear local error matters most.

**Fixed.** Both are runtime `InvalidArgumentException` guards in every build
mode, raised before the request is built.

### F6 — Credentials sent to a cleartext transport (V-32-adjacent)

**Location:** `lib/src/client/puente_config.dart:194`.

`baseUrlOverride` accepted any URI, including `http://`, for
`PuenteEnvironment.production`. Confirmed: a config with a live-shaped key and
`http://attacker.example.com/v1` constructed without complaint. The bearer
token, the CLABE, the beneficiary name, and the raw sensitive identifier
submitted via `updateProfile` would all travel in the clear and be modifiable
in transit.

**Fixed.** Cleartext `http://` is refused for any non-loopback host.
`http://127.0.0.0/8`, `http://localhost`, `::1`, the `mock` environment, and
every `https://` URL are unaffected, so the local-development path the option
exists for still works.

### F7 — Key material emitted to observers (V-58)

**Location:** `lib/src/transport/http_transport.dart:244` (was `_maskValue`).

`Authorization` was masked to first-4 + last-4, so `Bear…9876` put the final
four characters of the live secret into `PuenteObserver.onRequest` — a sink
whose entire purpose is to be forwarded to Sentry, OpenTelemetry, or a log
aggregator, i.e. a lower-trust system with long retention. There is no
operational benefit: `Idempotency-Key` and `X-Request-Id` are the correlators.

**Fixed.** The credential is masked to `Bearer ***` (scheme kept so a missing
header is distinguishable from a malformed one). `Idempotency-Key` keeps its
head/tail masking — it is a correlator, not a secret.

### F8 — A timed-out watch is indistinguishable from settlement

**Location:** `transfers_resource.dart:198`, `deposits_resource.dart:237`.

Both `watch` streams complete *normally* when the deadline passes without a
terminal state. A UI that treats `onDone` as success — the natural reading —
reports a still-in-flight transfer as finished. For a remittance screen that
is the wrong default.

**Fixed conservatively.** Both accept `throwOnTimeout` (default `false`, so no
existing caller changes behavior) which raises a `TimeoutException` naming the
last observed state. Flipping the default is a breaking change and is listed
under manual follow-up.

### F9 — `StaleQuoteException` dropped its support context and used a wall clock

**Location:** `resource_base.dart:62` (was `StaleQuoteException(message)`),
`stale_quote_exception.dart:39–40`.

A server-emitted `409 quote_expired` discarded `requestId` — on the one path
where a user is most likely to call support ("it said my quote expired"). The
exception also used `DateTime.now()`, the only place in `lib/` not reading the
ambient `clock`, making `withClock` tests non-deterministic.

**Fixed.** Both `requestId` and `idempotencyKey` are forwarded; timestamps read
`clock.now()`.

Two clarifications worth recording, because both look like findings and are
not:

- The webhook verifier's dual-format branch is **not** a signature-downgrade
  path. Selecting the raw-hex branch still requires an HMAC over the raw body
  under the same secret, which an attacker without the secret cannot produce.
- Caller-supplied headers overriding SDK headers
  (`http_transport.dart:225`) is deliberate and documented, and the caller is
  already trusted with the credential.

## Financial-system review

The core money design is sound and should be left alone: integer minor units
only, currency-tagged `Money` that throws on mismatch, no client-side fee/FX
math anywhere in `lib/`, and amounts that always originate from a backend
quote. `TransferIntent` is the right shape — the client submits a reference to
a server-computed quote, so there is nothing money-shaped for a client to get
wrong.

| Property | Before | Now |
|---|---|---|
| Idempotency on payment-initiating calls | `transfers.create`, `quotes.create`, deposits ✓; consents/corrections/account-update ✗ | ✓ across the board |
| Caller can retry safely after a timeout | ✗ — key discarded on the failure path | ✓ — `e.idempotencyKey` |
| Typed, branchable financial errors | ✓ — stable `code` prefixes preserved | ✓, plus `requestId` on stale-quote |
| Settlement-rail abstraction | ✓ — SPEI via CLABE, USDC/Solana via deposits; no rail-specific math client-side | unchanged |
| Audit trail support | ✓ — `deposits.events` append-only; `requestId` on exceptions | improved (F9) |

Two rail-level observations for the maintainer, neither a code defect:

- **SPEI is irrevocable once settled.** `transfers.cancel` correctly answers
  `409 terminal_state` after settlement. Worth stating in the README that
  "cancel" is a pre-settlement window, not a reversal — callers coming from a
  card-processing background will assume a refund path exists.
- **`reportSubmission`'s transaction hash is a hint**, with the backend
  verifying settlement independently. That is the right design and the doc
  comment says so; keep it that way.

## Manual follow-up

These need a product or maintainer decision and were deliberately **not**
changed.

1. **Replay window on the raw-hex webhook path (V-25).** The Stripe-style
   format enforces a ±5 min timestamp window; the Etherfuse-shaped raw-hex
   format carries no timestamp, so a captured delivery can be replayed
   indefinitely. This is a property of the upstream format, not a bug here.
   The fix belongs in the consuming server: dedupe on event id at the point of
   effect. Worth documenting in `server.dart`.
2. **Flip `throwOnTimeout` to `true` in 0.7.0** (F8). Correct default for
   money movement; breaking, so it needs a major-ish release note.
3. **`Quote.exchangeRate` degrades to `0` on an unparseable `fx_rate`.**
   `test/models/quote_test.dart:112` asserts this deliberately, and money
   amounts come from minor units so no math is wrong — but a send screen can
   render "1 USD = 0.00 MXN". I reverted my change on finding the test: this
   is a maintainer's call between resilience and loud failure, not an
   oversight to fix unilaterally.
4. **`sendMockEvent` on `deposits` and `kyc` ships in the production API
   surface.** Server-gated (403/404 on live), so not exploitable, but it puts
   test-only verbs in front of every consumer. Consider moving to
   `package:puente_railway/testing.dart`.
5. **`Retry-After` is capped at `maxRetryDelay` (10s default).** A server
   asking for 60s gets retried at 10s. Defensible, but it means the SDK can
   ignore an explicit backpressure signal under sustained rate limiting.
6. **Add a dependency-audit step to CI.** `dart pub outdated` is advisory
   only; there is no OSV/CVE gate today.
7. **`docs/contract-status.md` is superseded** and says so in a banner, but
   still leads with a "none of the methods work" TL;DR. Consider archiving it
   under `docs/history/` so a new reader cannot mistake it for current.
